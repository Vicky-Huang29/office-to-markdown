# Office to Markdown

将 Word（`.docx`）和 PowerPoint（`.pptx`）文件转换为 UTF-8 Markdown，并将支持的嵌入图片导出为本地资源，便于整理操作手册、迁移知识库和继续编辑文档。

## 项目解决什么问题

Office 操作手册中的标题、编号、表格和截图，直接复制为纯文本后容易丢失结构。本项目提供一个本地运行的 Python 命令行脚本，提取这些内容，生成可阅读、可编辑且使用相对路径引用图片的 Markdown 文件。

当前脚本接受 `.docx` 和 `.pptx`。旧版 `.doc`、`.ppt` 需要先用其他工具另存为对应的新格式。

## 主要功能

| 功能 | DOCX | PPTX |
| --- | --- | --- |
| 文本与标题 | 按正文顺序提取段落；识别 `Heading N` 标题样式，最多输出六级标题 | 每个保留的幻灯片生成一个一级标题，包含原始页码和可识别的标题 |
| 编号 | 根据段落直接设置的编号定义，输出常见数字、字母及部分圈号编号 | 读取段落直接设置的自动编号；`circleNumDbPlain` 输出圈号，其他类型输出数字加句点 |
| 图片 | 导出正文段落中引用的嵌入图片 | 导出幻灯片顶层的图片形状 |
| 表格 | 转为 Markdown 表格，默认用首行作为表头 | 暂不支持 |
| 内容整理 | 清理多余空行 | 提取组合形状内的文本；普通内容按从上到下、从左到右排序 |
| 可选处理 | — | 按简单规则跳过部分过渡页；对标题为“业务要点”的页面尝试合并预设字段和值 |

转换在本地完成，脚本不调用远程服务，也不需要 API Key。

## 安装方法

1. 安装 Python，建议使用 Python 3.10 或更新版本，确保终端可以执行 `python`。
2. 下载或复制本项目，进入包含 `SKILL.md` 和 `scripts/` 的项目根目录。
3. 安装依赖；如需隔离依赖，可在虚拟环境中执行：

   ```powershell
   python -m pip install lxml python-pptx
   ```

`lxml` 是脚本启动时必需的依赖；`python-pptx` 用于 PPTX 转换，只转换 DOCX 时可仅安装 `lxml`。不需要安装 Microsoft Office 或 LibreOffice。

检查命令入口：

```powershell
python scripts/office_to_markdown.py --help
```

## 使用方法

以下命令均在项目根目录运行。

转换 Word 文件：

```powershell
python scripts/office_to_markdown.py "操作手册.docx" "output"
```

转换 PowerPoint 文件：

```powershell
python scripts/office_to_markdown.py "培训材料.pptx" "output"
```

转换 PPTX 时尝试跳过部分过渡页：

```powershell
python scripts/office_to_markdown.py "培训材料.pptx" "output" --skip-transition-slides
```

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `input` | 是 | 单个 `.docx` 或 `.pptx` 文件路径；扩展名不区分大小写 |
| `output_dir` | 是 | 输出目录，不存在时自动创建 |
| `--skip-transition-slides` | 否 | 仅对 PPTX 生效；默认保留全部幻灯片 |

路径中有空格时请加引号。每次命令处理一个文件，当前没有批量转换或递归扫描目录的参数。

输出按输入文件名（去掉扩展名）命名：

```text
output/
├── 操作手册.md
└── 操作手册_assets/
    └── image-001.png
```

图片扩展名由源图片决定；没有导出图片时，资源目录为空。分享或移动结果时，请同时保留 `.md` 和对应的 `_assets` 目录，并保持两者的相对位置。

同一输出目录中的同名结果会被覆盖，已有的 `_assets` 目录会先被删除再重建；转换失败时也可能已清空该资源目录。需要保留旧结果时，请使用新的输出目录。名称相同的 DOCX 和 PPTX 也会使用相同的输出名称。

## 输入输出示例

以下为最小示例，示例 Office 文件未随项目附带。

### DOCX 示例

输入 `操作手册.docx` 包含：

- 一级标题“操作手册”和二级标题“准备材料”，分别使用 Word 的 `Heading 1`、`Heading 2` 样式。
- 段落“进入系统”，直接设置从 1 开始、格式为 `(%1)` 的自动编号。
- 一个两列表格，表头为“项目 / 说明”，内容为“输出格式 / Markdown”。
- 正文中的一张 PNG 图片。

运行前面的 Word 转换命令后，`output/操作手册.md` 内容为：

```markdown
# 操作手册

## 准备材料

（1） 进入系统

| 项目 | 说明 |
| --- | --- |
| 输出格式 | Markdown |

![](操作手册_assets/image-001.png)
```

在 Windows 上，终端输出为：

```text
output\操作手册.md
images=1
```

第一行是生成的 Markdown 路径，`images=1` 表示本次导出了一个图片文件。

### PPTX 示例

输入 `培训材料.pptx` 的第一张幻灯片使用标题占位符“提交申请”，正文文本框有两个段落：“打开页面”“提交资料”，均直接设置 `circleNumDbPlain` 自动编号。默认转换结果为：

```markdown
# 幻灯片 1：提交申请

① 打开页面

② 提交资料
```

若跳过某些幻灯片，输出仍使用原始页码，例如可能从“幻灯片 1”直接到“幻灯片 3”。

## 支持范围与限制

- **图片内文字**：没有 OCR，不自动识别截图、二维码或照片中的文字；导出的图片引用使用空的 alt 文本。
- **Word 结构**：主要处理正文顶层段落和表格；页眉、页脚、脚注、批注及表格内图片不在当前提取范围。复杂编号继承、编号重启、合并单元格等需要人工核对。
- **PPT 排版**：不还原完整视觉布局，不导出组合形状内的图片，也不提取表格、图表、SmartArt 或备注。自动编号的起始值和复杂层级可能无法还原。
- **过渡页判断**：`--skip-transition-slides` 使用启发式规则：页面没有顶层图片，除标题外的顶层文本形状合计只有一至两行非空文本，且至少一行为纯数字；不递归检查组合形状。它不保证识别所有封面、目录或结束页，也可能跳过符合该规则的内容页。
- **字段匹配**：只有标题为“业务要点”的 PPT 页面启用专门匹配，预设字段为“票据类型、账户要求、提票渠道、融资要求、持票人属地要求、营业时间”，并按位置选择下方的值；复杂布局可能错配。
- **格式保留**：不保留原始字体、颜色和完整页面布局，也没有通用的粗体、超链接、公式等格式转换。

转换后请对照原文件抽查标题、编号、表格和图片，尤其是复杂 PPT 的内容顺序与字段对应关系。
